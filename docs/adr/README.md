# ADR (작업·결정 기록)

PR마다 이 폴더에 기록을 하나 남긴다. 무엇을 왜 바꿨는지, 어떻게 확인했는지를 적는다.
작은 수정도 남긴다. 짧아도 된다.

## 규칙

- PR마다 파일을 하나 추가하거나 기존 파일을 고친다.
- `.github/workflows/adr-check.yml`이 PR을 검사한다. 이 폴더에 바뀐 기록이 없으면 PR이 실패한다. 필수 항목이 빠지거나 작업 내용이 비어 있어도 실패한다.
- 파일 이름은 `YYYY-MM-DD-짧은-제목.md`로 한다. 날짜는 작성한 날이다.
  - 번호를 쓰지 않는다. 브랜치 여러 개가 같은 번호를 잡으면 겹치기 때문이다.
  - 같은 날 같은 제목이 있으면 끝에 `-2`를 붙인다.
- `_template.md`를 복사해서 쓴다. 아래 다섯 항목은 꼭 채운다.
  - 상태: 제안, 채택, 대체됨 중 하나
  - 맥락: 왜 이 작업을 했는지
  - 결정: 무엇을 하기로 했는지
  - 작업 내용: 실제로 바꾼 것. 파일, 설정, 서버나 외부 서비스에서 한 일까지
  - 확인 방법: 어떻게 확인했는지. 테스트, 개발 서버에서 본 것
- 영향(되돌리는 법, 남은 일)은 있으면 적는다.
- 결정이 바뀌면 옛 파일을 지우지 않는다. 상태를 `대체됨: 새 파일 이름`으로 바꾸고 새 파일을 쓴다.
- develop에서 main으로 체리픽하는 PR은 따로 쓰지 않아도 된다. develop에서 쓴 기록이 커밋에 같이 들어가 있다.

## 다른 문서

팀 문서는 계속 노션 위키("개발 저장소 문서 모음")에 둔다. 저장소에는 `docs/` 아래 md만 올린다.
